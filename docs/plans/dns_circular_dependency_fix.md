# DNS Circular Dependency Fix Plan

## Goal
Avoid circular dependencies between platform infrastructure and CoreDNS service in Docker environment.

## Problem Summary
1. Docker container orchestrates its own DNS
2. Platform uses internal *.local.test domain for service discovery
3. CoreDNS service should only resolve *.local.test references
4. Docker daemon must use systemd-resolved (127.0.0.53) for external DNS

## Solution Architecture
1. CoreDNS Service
   - Runs in isolated Docker container
   - Only serves *.local.test DNS queries
   - Port 53 NOT exposed to Docker daemon
2. Docker Daemon
   - Uses systemd-resolved for DNS resolution
   - Systemd-resolved handles both internal and external DNS
3. Service Discovery
   - `.local.test` suffix handled by Docker embedded DNS (127.0.0.11)
   - External domains resolved through systemd-resolved

## Configuration Implementation
### 1. Modified infrastructure/compose.yml
```yaml
# Previously:
services:
coredns:
  image: coredns/coredns:1.11.1
  container_name: infra_dns
  ports:
    - "53:53/udp"
    - "53:53/tcp"

# Modified (port 53 removed)
services:
coredns:
  image: coredns/coredns:1.11.1
  container_name: infra_dns
  # No port mapping to prevent core dns from acting as system resolver
  environment:[]

# Added Docker daemon.json configuration
volumes:
  - infrastructure/configs/docker/daemon.json:/etc/docker/daemon.json

### 2. New daemon.json configuration
```json
{
  "dns": ["127.0.0.53"],
  "dns-search": ["."]
}
```

### 3. Updated resolv.conf
Generated by systemd-resolved:
```
nameserver 127.0.0.53
options edns0 trust-ad
search .
```

## Verification Steps
1. Test DNS resolution in new container
   ```bash
docker run --rm -it alpine nslookup registry-1.docker.io
```

2. Validate CoreDNS service operation
   ```bash
docker inspect infra_dns | grep -i dns
```

3. Check Docker daemon DNS configuration
   ```bash
docker info | grep -i dns
```

4. Confirm system resolver behavior
   ```bash
resolvectl status
systemd-resolve --status
```

## Expected Behavior
- Docker daemon uses systemd-resolved for DNS
- Internal services resolved via `.local.test` suffix
- External domains resolved through upstream DNS servers

## Dependency Matrix
| Component      | Provider                | Network Policy                  |
|----------------|-------------------------|---------------------------------|
| Docker Daemon  | systemd-resolved        | Internal: Use .local.test       |
| Package Manager| CoreDNS (127.0.0.1)     | Only .local.test suffixes       |
| Registry       | Docker pull service     | Resolved by systemd-resolved    |

This completes the circular dependency fix while maintaining ADR011 compliance and PAT009 architectural requirements.
